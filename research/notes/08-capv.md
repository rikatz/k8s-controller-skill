HEADLINE CAVEAT: CAPV is NOT "pure controller-runtime". It sits on top of cluster-api (CAPI) helper libs everywhere: `capicontrollerutil.NewControllerManagedBy`, `patch.NewHelper` from cluster-api/util/patch, `finalizers.EnsureFinalizer`, `paused.EnsurePausedCondition`, `clustercache`, `crdmigrator`, `conversionclient`, CAPI condition utils (v1beta2 `conditions.Set`). ## 1. Manager setup (main.go, pkg/manager/manager.go)

- [V] One manager, many controllers (up to ~10): govmomi mode registers 5 controllers (main.go:683-696), supervisor mode up to 6 (main.go:729-751), plus ClusterCache and CRDMigrator. Mode is chosen at runtime by detecting which CRDs exist (main.go:322-340 uses `apiutil.NewDynamicRESTMapper` + `wait.PollUntilContextTimeout(ctx, 5*time.Second, 30*time.Second, true, ...)`; `isCRDDeployed` main.go:766 uses `meta.IsNoMatchError`). Pattern: "skip controllers whose CRD is not installed" - a provider-style need, not generally applicable.
- [V] Per-controller concurrency flag, one per controller, via tiny helper:
  `func concurrency(c int) controller.Options { return controller.Options{MaxConcurrentReconciles: c} }` (main.go:777). Defaults high: vspheremachine 100, vspherevm 100, vspherecluster 50, identity/zone 10 (main.go:142-169). The Options value is passed into each `AddXControllerToManager(..., options controller.Options)` and applied with `.WithOptions(options)` (vspherevm_controller.go:88).
- [V] Client rate limits: `--kube-api-qps` default 100, `--kube-api-burst` default 200 (main.go:233-236), applied to rest.Config (main.go:307-308). Separate `--clustercache-client-qps/burst` 20/30 for workload-cluster clients (main.go:239-242, 783+). UserAgent and WarningHandler set on rest.Config (main.go:309-310).
- [V] Leader election flags: `--leader-elect` default true, lease 15s / renew 10s / retry 2s (main.go:203-212), mapped to `managerOpts.LeaseDuration/RenewDeadline/RetryPeriod` (main.go ~585-587). `--leader-election-id` flag.
- [V] Cache options (main.go:429-437 onward): `DefaultNamespaces` from `--namespace`, `SyncPeriod`, `DefaultTransform: cache.TransformStripManagedFields()`, `ByObject` with per-type label selectors and Transform funcs that null out unused data. Excerpt:
  `byObject[&corev1.Secret{}] = cache.ByObject{ Label: clusterSecretCacheSelector, Transform: func(in any)(any,error){ ... s.Data = nil ...` (main.go ~455-468). Also strips `Spec`/`Status` from MachineSet and KCP to what is needed (main.go ~480-520). Very strong memory-optimisation example. Caveat: transforms that drop fields mean readers MUST NOT use those objects for anything else; they document this in comments.
- [V] Client cache bypass: `client.Options{Cache:&client.CacheOptions{DisableFor: []client.Object{&corev1.Secret{}}}}` (main.go ~540-552), with a second explicit "secretCachingClient" built from `client.New(..., Cache:{Reader: mgr.GetCache()})` (main.go ~565-572) for the few places that do want the (label-filtered) cached Secret. Good pattern: make the cached-vs-uncached decision explicit per client.
- [V] Controller global options: `managerOpts.Controller = config.Controller{UsePriorityQueue: ptr.To[bool](feature.Gates.Enabled(feature.PriorityQueue)), CacheSyncTimeout: 5*time.Minute}` (main.go:613-618). PriorityQueue is behind a feature gate.
- [V] Webhook server: `webhook.NewServer(webhookOpts)` with `--webhook-port` 9443 and `--webhook-cert-dir` flags, TLS opts from CAPI flag helper (main.go:604-607). Readiness AND health checks both use `mgr.GetWebhookServer().StartedChecker()` (main.go:754-764). Note: webhook-up in healthz means a slow webhook start can fail liveness - [U] not verified as a problem.
- [V] Diagnostics/metrics: not hand-rolled - `capiflags.AddManagerOptions(fs,&managerOptions)` / `capiflags.GetManagerOptions` (main.go:261, 604) return TLS options and `metricsserver.Options`; RBAC markers for tokenreviews/subjectaccessreviews for the authenticated metrics endpoint live in main.go:266-267 ("Add RBAC for the authorized diagnostics endpoint"). Metrics flags themselves are in CAPI, [U] exact default bind addr.
- [V] Scheme: constructed empty (`managerOpts.Scheme = runtime.NewScheme()`, main.go ~428) and populated inside `manager.New` with a wall of `utilruntime.Must(X.AddToScheme(opts.Scheme))` (pkg/manager/manager.go:62-80, 18 groups incl. both vm-operator versions). Not `init()`-time global scheme. Good.
- [V] Feature gates: k8s `component-base/featuregate`; `feature.AddFlag(fs,&featureGates,...)` (main.go:262), gates declared with owner/alpha comments template (feature/feature.go:25-70), set in main.go:365-380 before controllers are built. Gates conditionally add watches (vspherecluster_controller.go:~84-92, KCP watch) and whole controllers (main.go:745).
- [V] Logging: klog via `ctrl.SetLogger(klog.Background())` (main.go:~290). Log messages here are often `fmt.Sprintf`-built (15 `Info(fmt.Sprintf(` in controllers/) rather than static message + KV pairs, and many start with capital letters but some ("failed to wait on func") don't. Mixed.
- [V] Shutdown: `ctx := ctrl.SetupSignalHandler()` (main.go:~297); `defer session.Clear()` on exit (main.go ~645).
- Smell [V]: `os.Exit(1)` sprinkled through `main()` after `setupLog.Error` (dozens); a `defer` after `os.Exit` paths won't run. Also `main.go` is 845 lines and mixes flag parsing, CRD detection, cache tuning and wiring.

## 2. Controller structure

### Registration function, not a method
- [V] Each controller is `AddXControllerToManager(ctx, controllerManagerCtx, mgr, [deps], options controller.Options) error` that builds the reconciler struct then the builder (vspherevm_controller.go:~73-125). There is NO `SetupWithManager` on the reconcilers (except crdmigrator/clustercache which come from CAPI). Dependencies (clusterCache, VMService) are injected into the struct here - good for testing.
- [V] Builder is `capicontrollerutil.NewControllerManagedBy(mgr, predicateLog)` (CAPI wrapper; vspherevm_controller.go:85) with `.For().WithOptions().Watches().WatchesRawSource().WithEventFilter().Owns().Complete(ctx, r)`. Note `Complete(ctx, r)` takes a ctx - this is the CAPI wrapper's signature, NOT controller-runtime's `Complete(r)`. [U] internals of wrapper (in cluster-api repo, not read) - presumably adds typed predicate logging/name defaults.

Excerpt (vspherevm_controller.go:85-123):
```
return capicontrollerutil.NewControllerManagedBy(mgr, predicateLog).
    For(&infrav1.VSphereVM{}).
    WithOptions(options).
    WatchesRawSource(source.Channel(controllerManagerCtx.GetGenericEventChannelFor(infrav1.GroupVersion.WithKind("VSphereVM")), &handler.EnqueueRequestForObject{})).
    WithEventFilter(predicates.ResourceHasFilterLabel(mgr.GetScheme(), predicateLog, controllerManagerCtx.WatchFilterValue)).
    Watches(&clusterv1.Cluster{}, handler.EnqueueRequestsFromMapFunc(r.clusterToVSphereVMs)).
    Watches(&infrav1.VSphereCluster{}, handler.EnqueueRequestsFromMapFunc(r.vsphereClusterToVSphereVMs), predicate.Funcs{ UpdateFunc: ..., CreateFunc: func(event.CreateEvent) bool { return false }, ...}).
    Watches(&ipamv1.IPAddressClaim{}, handler.EnqueueRequestsFromMapFunc(r.ipAddressClaimToVSphereVM)).
    WatchesRawSource(r.clusterCache.GetClusterSource("vspherevm", r.clusterToVSphereVMs)).
    Complete(ctx, r)
```
- [V] Watch patterns used: `For` + `Owns(vm)` (vspheremachine_controller.go:138; owned VirtualMachine via `conversionclient.WatchObject`, :105); mapping fns `handler.EnqueueRequestsFromMapFunc`; CAPI's stock `clusterutilv1.MachineToInfrastructureMapFunc(GVK)` (:118); per-watch `predicate.Funcs` with all four funcs filled in explicitly (return false on Create/Delete/Generic); global `WithEventFilter(predicates.ResourceHasFilterLabel(...))` implementing the `--watch-filter` label convention (CAPI convention, lets multiple provider instances share a cluster); `predicates.ClusterPausedTransitionsOrInfrastructureProvisioned` (:123) to avoid reconciling every Cluster update.
- [V] Typed-ness: `predicate.Funcs` on `Watches(&X{})` does manual type assertions `e.ObjectOld.(*infrav1.VSphereCluster)` unchecked (vspherevm_controller.go:109-110) -> would panic on wrong type; the supervisor KCP one checks `ok` (vspherecluster_controller.go:~96). Inconsistent; with CR v0.25 the typed `predicate.TypedFuncs[*T]` is the better idiom. [V] they use the untyped form.
- [V] Out-of-band events: `WatchesRawSource(source.Channel(...))` fed by a per-GVK `chan event.GenericEvent` cached in a `sync.Map` on the shared manager context (pkg/context/controller_manager_context.go:83-90, UNBUFFERED `make(chan event.GenericEvent)`). Comment in code explains purpose: "useful when there are events outside of Kubernetes that should cause a resource to be synchronized, such as a goroutine waiting on some asynchronous, external task" (vspherevm_controller.go:91-93).
- [V] Workload-cluster watches: `clusterCache.GetClusterSource("vspherevm", mapFn)` (:123) - CAPI clustercache as a source.
- [V] RBAC markers are placed above each `AddXControllerToManager` function in controllers/*.go, and manager-level ones in main.go:266-275 (including `resourceNames=` scoped CRD update/patch for the CRD migrator - a nice least-privilege example, main.go:271). Makefile runs rbac gen over `paths=./ paths=./controllers/...` (Makefile:327-330).

### Reconciler struct / context object
- [V] Reconciler structs hold only deps: `vmReconciler{Recorder, *ControllerManagerContext, VMService, clusterCache}` (vspherevm_controller.go:127-132). Embeds a shared `*capvcontext.ControllerManagerContext` (Client, Logger, Scheme, Namespace, Username/Password, WatchFilterValue, generic event channels) - a fat "god context" (pkg/manager/manager.go:92-108) [smell, see section 10].
- [V] Per-reconcile "context object" pattern: `capvcontext.VMContext{ControllerManagerContext, VSphereVM, VSphereFailureDomain, Session, PatchHelper}` (vspherevm_controller.go:~246-252), with a `Patch(ctx)` method listing owned conditions (pkg/context/vm_context.go:47-60). Same for ClusterContext/MachineContext. Pre-dates the Go idiom of passing small explicit args; it implements `String()` and is passed to log/error messages (`pkgerrors.Errorf("unknown task state %q for %q", ..., vmCtx)` util.go ~190). Note: it mixes a `context.Context`-named type with stdlib context - they correctly still pass `ctx context.Context` as the first param separately.

### Reconcile body shape (vspherevm_controller.go:135-345)
1. Get object; `IsNotFound` -> `Result{}, nil` (:139-146).
2. `finalizers.EnsureFinalizer(ctx, r.Client, obj, VMFinalizer)`; `if added || err { return }` - returns immediately after adding finalizer and relies on the update event to re-enqueue (:158-160). Comment: "Add finalizer first if not set to avoid the race condition between init and delete." For VSphereMachine, finalizer is only added AFTER the CAPI Machine ownerRef exists (vspheremachine_controller.go:253-255).
3. `patch.NewHelper(obj, r.Client)` created BEFORE any mutation (:163).
4. `paused.EnsurePausedCondition(...)` early-out (:168).
5. Resolve chain of owners (VSphereMachine -> VSphereCluster -> Machine); if owner ref not yet set, log and `return Result{}, nil` - relying on a watch on the owner to re-trigger (:203-228).
6. Build context struct; `defer` a closure that (a) sets always-present conditions, (b) computes summary Ready condition, (c) `vmContext.Patch(ctx)`, aggregating errors into named return `reterr` via `kerrors.NewAggregate` (:262-345). Signature uses named return: `(_ ctrl.Result, reterr error)`.
7. `if !DeletionTimestamp.IsZero() { reconcileDelete } else { reconcileNormal }` (:369-373).
- [V] Deletion: `reconcileDelete` marks conditions Deleting, calls `VMService.DestroyVM`, requeues while VM state != NotFound, best-effort deletes the K8s Node (log + continue on error, :410-414), deletes IPAddressClaims, THEN `ctrlutil.RemoveFinalizer` (:420). Cluster delete: waits (RequeueAfter 10s) until all VSphereMachines are gone, then reconciles cluster modules (needs vCenter creds so must precede Secret removal - commented), then removes the identity-Secret finalizer and deletes the Secret, then removes own finalizer (vspherecluster_reconciler.go:182-262). Good explicit ordering with comments.
- [V] Cache-staleness fix after patch: if `Status.TaskRef` changed, poll the (cached) client up to 5s at 5ms until the cache shows the new value, to avoid duplicate vCenter tasks (vspherevm_controller.go:~325-340, `wait.PollUntilContextTimeout(ctx, 5*time.Millisecond, 5*time.Second, true, ...)`). This is a genuine, honest answer to "my cache is stale after my own write, and my side effect is non-idempotent". Smell: it blocks a worker for up to 5s and polls the cache in a tight loop; alternatives are annotate-before-act or write-via-uncached-reader.

## 3. Slow / rate-limited external system (vCenter)

- [V] Sessions: process-wide `sessionCache sync.Map` + a single global `sessionMU sync.Mutex` held for the WHOLE of `GetOrCreate`, including network login (pkg/session/session.go:45-49, 123-124). Key = `server#datacenter#username#sha256(password)` (:128-131). On cache hit, validity is probed with `SessionManager.UserSession` and `TagManager.Session` (two round trips per reconcile), logs out if inactive, creates new otherwise. Smell [V]: a single mutex serialises session creation across ALL concurrent reconciles (up to 100 workers) and across vCenters - one slow vCenter blocks all. Copy the "cache by (endpoint,identity,secret-hash)" idea, not the global lock (use per-key lock/singleflight).
- [V] vCenter unreachable => condition `VCenterAvailable=False` reason `VCenterUnreachable`, return the error (so controller-runtime rate-limited backoff applies) (vspherevm_controller.go:176-185). No custom backoff.
- [V] Async tasks are persisted in status: `Status.TaskRef` (the vSphere task MoRef) and `Status.RetryAfter` (api/govmomi/v1beta2/vspherevm_types.go:283-293). Every mutating vCenter call stores `TaskRef = task.Reference().Value` (service.go:285, 324, 385, 419, 525, 552, 749). At the START of each reconcile `reconcileInFlightTask` is run: if task Queued/Running => return "in flight", success => clear TaskRef, error => set TaskFailed condition and set `RetryAfter = now+1m`, next pass clears it (pkg/services/govmomi/util.go:127-210). This is the key idempotency mechanism: external operation identity lives in `.status`, observed before acting, not a requeue-timer guess. Uses `findVM` by BIOS UUID rather than assuming create succeeded (service.go:~75).
- [V] Wake-up instead of poll: a deferred `reconcileVSphereVMOnTaskCompletion` spawns a goroutine that `taskHelper.WaitForResult(context.Background())` (explicitly NOT the reconcile ctx - comment says it may time out) then pushes a `GenericEvent` to the channel registered via `WatchesRawSource` (util.go:263-335, service.go:~79). On task error it deliberately does NOT enqueue ("we don't want to retry right away") and relies on RetryAfter. Caveats [V]: (a) goroutine per in-flight task, unbounded, no dedupe: a re-reconcile while task running spawns another waiter; (b) after controller restart all in-flight waiters are lost - recovered only by resync/other events [U: whether SyncPeriod covers it]; (c) send on unbuffered channel blocks the goroutine if the manager is shut down; (d) `obj := vmCtx.VSphereVM.DeepCopy()` sent as the event object (fine). Alternative that is more restart-safe: `RequeueAfter` while task is running.
- [V] Requeue vs error: uses `RequeueAfter: 10*time.Second` (waiting for VSphereMachines to delete, cluster delete :213; waiting for IP :524) and `RequeueAfter: time.Until(Status.RetryAfter.Time)` (:491). Mostly returns `Result{}, nil` and relies on watches ("waiting for owner").
- [U/V] `reconcile.TerminalError` is NOT used anywhere in non-test code (grep returned nothing). Permanent failures (bad credentials, bad spec) are returned as normal errors => infinite backoff retry. This is a gap for a "what to do better" list.
- [V] Per-resource condition rather than fatal stop for "NotFoundByBIOSUUID" - treated as potentially transient (service.go:~88-98).

## 4. Conditions & status

- [V] Dual-API conditions during a migration: legacy CAPI v1beta1-style `deprecatedv1beta1conditions.MarkFalse(obj, type, reason, ConditionSeverityError, "%v", err)` AND new `metav1.Condition` via CAPI `conditions.Set(obj, metav1.Condition{Type,Status,Reason,Message})` are written side by side at every site (vspherevm_controller.go:176-193, service.go:80-136, util.go:175-185). 102 references in controllers/. Severity (Info/Warning/Error) exists ONLY on the deprecated path; the new path has no severity. Do NOT copy the dual-write; it exists for CAPI v1beta1->v1beta2 transition. What to copy: the v1beta2 side.
- [V] Condition types and reasons are exported string constants grouped per condition with doc comments, in the API package (api/govmomi/v1beta2/vspherevm_types.go ~line 40-135): `VSphereVMReadyCondition = clusterv1.ReadyCondition`, `VSphereVMVirtualMachineProvisionedCondition = "VirtualMachineProvisioned"`, reasons `"WaitingForClone"`, `"TaskFailed"`, `"NotFoundByBIOSUUID"`, `"VCenterUnreachable"`, ... Reuse of CAPI-wide reason constants where semantics match (`clusterv1.DeletingReason`, `NotProvisionedReason`). Reasons are CamelCase, distinct per condition (reuse of `WaitingForIPAddress` string in two different conditions).
- [V] "Ready" is a computed summary: `conditions.SetSummaryCondition(obj, obj, ReadyCondition, ForConditionTypes{...}, IgnoreTypesIfMissing{...}, CustomMergeStrategy{...})` run in the deferred function so it's always recomputed (vspherevm_controller.go:~290-320). Ensure "set at first reconcile" for the primary condition (comment at :267-270, CAPI guideline).
- [V] Patch ownership is explicit: `patch.WithOwnedConditions{Conditions: []string{...}}` (vm_context.go:55, vspherecluster_reconciler.go:~165) so the patch helper only touches conditions this controller owns - prevents clobbering conditions set by other controllers/CAPI (e.g. Paused).
- [V] observedGeneration: `Paused` handling via `paused.EnsurePausedCondition`; [U] whether each condition carries `ObservedGeneration` is handled inside CAPI `conditions.Set` (it sets it from the object generation in CAPI v1beta2 util - not verified by reading). KAL linter enforces conditions shape (`conditions` linter).
- [V] Status shape: `conditions` listed first in status with `+listType=map +listMapKey=type +kubebuilder:validation:MaxItems=32` (vspherevm_types.go:236-244, KAL `conditions.isFirstField`). Status has `ready *bool` (required by CAPI contract, "required at runtime for other controllers that read this CRD as unstructured data" :253-257) - KAL `nobools` is explicitly excluded for this (.golangci-kal.yml). `RetryAfter metav1.Time` and `taskRef` as operational state in status.
- [V] No failureReason/failureMessage in v1beta2 types (moved to conditions, per CAPI v1beta2 contract) [U: still present in v1beta1 types, not checked].

## 5. Webhooks

- [V] Current generic builder API: `ctrl.NewWebhookManagedBy(mgr, &infrav1.VSphereVM{}).WithValidator(webhook).WithDefaulter(webhook).WithConverter(conversion.VSphereVM).Complete()` (internal/webhooks/vspherevm.go:46-52). Type-parameterized interfaces: `var _ admission.Validator[*infrav1.VSphereVM] = &VSphereVM{}`, `admission.Defaulter[*infrav1.VSphereVM]`; methods get typed objects (`Default(_ context.Context, typedObj *infrav1.VSphereVM) error`, `ValidateUpdate(_ ctx, oldTyped, newTyped *T) (admission.Warnings, error)`). No `runtime.Object` casts. This is the new (CR >= ~0.22) API; copy it.
- [V] Webhook structs are empty `struct{}` with no fields; `+kubebuilder:webhook:` markers sit directly above the type (vspherevm.go:36-37). Marker uses explicit `matchPolicy=Equivalent, sideEffects=None, admissionReviewVersions=v1, failurePolicy=fail`; path names are `/validate-...-v1beta2-vspherevm` (default scheme). Both mutating and validating from one struct.
- [V] Conversion webhook: `WithConverter(conversion.X)` - a CAPI-style "hub/spoke" converter (internal/webhooks/conversion + pkg/conversion), NOT the old `Hub()/ConvertTo/ConvertFrom` on the API types; conversion code lives in `internal/` outside the `api` module so the API package stays dependency-light (api/ is a separate Go module with only k8s + cluster-api/api deps: api/go.mod). Fuzz round-trip tests via `utilconversion.SpokeConverterFuzzTestFunc` (internal/webhooks/conversion/*_test.go).
- [V] Immutability in Go, whole-spec style: ValidateUpdate converts both objects to unstructured, deletes allow-listed keys, then `reflect.DeepEqual` the rest and returns `field.Forbidden(spec, "cannot be modified")` (vspherevm.go:~84-122). Compact allow-list but untyped: map-key strings (`"guestSoftPowerOffTimeoutSeconds"`) are not compiler-checked, and unchecked `.(map[string]interface{})` assertions would panic if spec is empty/omitzero [V:`newVSphereVMSpec["network"].(map[string]interface{})` :~104]. Also error says "cannot be modified" for the whole spec rather than field path.
- [V] CEL vs webhook split: supervisor API (newer code) uses CEL transition rules on types: `+kubebuilder:validation:XValidation:rule="!has(oldSelf.provider) || self.provider == oldSelf.provider",message="provider is immutable once set"` (api/supervisor/v1beta2/vspherecluster_types.go:168, also :153,167,188; vspheremachine_types.go:496). Older govmomi API uses webhook code for the same job. Evidence of the migration direction: new immutability -> CEL; webhooks remain for cross-field/defaulting/cross-object lookups (supervisor webhooks take `mgr.GetClient()` + networkProviderFactory, main.go:705-718).
- [V] Errors aggregated through helper `AggregateObjErrors(gk, name, allErrs)` returning `apierrors.NewInvalid` (internal/webhooks/util.go).
- [V] Two-layer indirection: public `webhooks/alias.go` re-exports internal webhook structs so `main` (outside module internal/) can wire them - exists because of the multi-module layout, not good design to copy.
- [V] Defaulting is in a webhook (`Spec.OS = Linux` when empty, vspherevm.go:54-59) NOT via `+kubebuilder:default` - on purpose: KAL `forbiddenmarkers` bans `kubebuilder:default`/`default` ("we prefer a clear signal on user intent", .golangci-kal.yml).

## 6. API types & markers

- [V] Separate Go module for API (`api/go.mod`, `sigs.k8s.io/cluster-api-provider-vsphere/api`), directories `api/govmomi/{v1beta1,v1beta2}` and `api/supervisor/{v1beta1,v1beta2}` - two API groups (`infrastructure...` and `vmware.infrastructure...`) for two modes. v1beta2 = storage version (`+kubebuilder:storageversion`, vspherevm_types.go:382); v1beta1 = spoke, kept generated by conversion-gen (`zz_generated.conversion.go`) for the supervisor group only.
- [V] Marker habits (vspherevm_types.go): every field has `// +optional` or `// +required` (:228, 394) (KAL `optionalorrequired`); strings: `MinLength=1` + `MaxLength=N` (:193-194); lists: `+listType=atomic|map`, `+listMapKey=type`, `MaxItems`, and `items:MinLength/MaxLength` (:263-266); ints with `Minimum=1` (:221); struct-level `+kubebuilder:validation:MinProperties=1` on Status (:235) to forbid empty `{}`; resource markers `+kubebuilder:object:root=true`, `+kubebuilder:resource:path=...,scope=Namespaced,categories=cluster-api`, `+kubebuilder:subresource:status` (:380-383) placed in a detached comment block above the type doc comment.
- [V] Doc style: godoc starts with the serialized JSON field name in lowerCamel ("biosUUID is the VM's BIOS UUID...", "conditions represents the observations of..."); enforced by KAL `commentstart`. Field docs include behavioral semantics ("If omitted, the mode defaults to hard.") instead of using `+default`.
- [V] json tags: `json:"spec,omitempty,omitzero"` for structs, `omitempty` for scalars, pointers where zero is meaningful (`Ready *bool`). Embeds with `json:",inline"`.
- [V] Registration: `objectTypes = append(objectTypes, &VSphereVM{}, &VSphereVMList{})` in each types file's `init()` and `addKnownTypes` in groupversion_info.go (hand-rolled instead of kubebuilder's `SchemeBuilder.Register`) (api/govmomi/v1beta2/groupversion_info.go:~30-40).
- [V] kube-api-linter: YES. `.golangci-kal.yml` runs `kubeapilinter` as a custom golangci-lint module (Makefile:182-184 builds `golangci-lint-kube-api-linter` from hack/tools/.custom-gcl.yaml, version read out of that file). Enabled: commentstart, conditions, conflictingmarkers, duplicatemarkers, forbiddenmarkers, integers, jsontags, maxlength, nobools, nodurations, nofloats, nomaps, nonullable, notimestamp, optionalfields, optionalorrequired, requiredfields, ssatags, statusoptional, statussubresource, uniquemarkers. `nophase` intentionally off. Scope excludes v1beta1 and carves out documented exceptions (nobools on existing v1beta2 fields; nomaps on `capacity`). Runs only on `api/` (`cd api; $(GOLANGCI_LINT_KAL) run`, Makefile:496-512). Excellent template for a skill's "API lint" step; it directly encodes the OpenShift-style "no booleans / enums / maxlength" rules.
- Smell [V]: despite `nobools`, `Ready *bool`, `retryAfter metav1.Time` (violates notimestamp/durations spirit) stay in status, grandfathered by exclusions.

## 7. Testing

- [V] Controller tests: Ginkgo + Gomega with an in-process envtest-backed manager shared by the package: `controllers_suite_test.go` builds `helpers.NewTestEnvironment(ctx)` (internal/test/helpers/envtest.go:140), registers all controllers with `controller.Options{MaxConcurrentReconciles: 10, SkipNameValidation: ptr.To(true)}` (needed because each test package re-registers same-named controllers), starts the manager in a goroutine, `<-testEnv.Manager.Elected()`, `testEnv.WaitForWebhooks(ctx)` (controllers_suite_test.go:~100-125). `TestMain` does setup/teardown (:46-50). JUnit report to `$ARTIFACTS` (:36-39).

## 9. Provider-specific (differs from CAPI core)

- Reconciles an infra object whose owner chain is Cluster -> (Machine -> VSphereMachine -> VSphereVM); needs CAPI helpers to find owners: `GetClusterFromMetadata`, `GetOwnerMachine`, label `cluster.x-k8s.io/cluster-name`. Controllers wait (return nil) for owner refs set by CAPI core instead of failing.
- Mapping functions are Cluster/Machine -> infra: `MachineToInfrastructureMapFunc`, custom `clusterToVSphereVMs`, `vsphereClusterToVSphereVMs`. Pause semantics via Cluster.spec.paused + annotation + predicates; watch-filter label for multi-instance.
- Needs `clustercache` (CAPI) for remote workload-cluster clients, with its own QPS/burst; core owns it conceptually, provider re-instantiates it in its own manager.
- Contract fields in status (`ready`, `addresses`) that CAPI reads as unstructured - provider cannot freely change them.
- Manager carries bootstrap credentials from a mounted file watched by fsnotify (`manager.InitializeWatch`, main.go ~636-642) and cached in a global; identity via `VSphereClusterIdentity` + Secret finalizers.
- CRD migrator controller (`crdmigrator`, from CAPI) registered at concurrency 1 "to ensure we don't overwhelm the apiserver" (main.go:588-597) - handles storage version migration; provider-ish need (clusterctl-managed CRDs).

## 10. Smells / what NOT to copy (honest list)

1. Depends on CAPI helper layers (`capicontrollerutil.NewControllerManagedBy(...).Complete(ctx, r)`, `patch.Helper`, `conditions`), so it is not a template for pure CR code. The non-CAPI equivalents are plain `ctrl.NewControllerManagedBy(mgr).For().Complete(r)` + `client.MergeFrom` / `Status().Patch`.
2. Dual condition systems (deprecated v1beta1 + v1beta2) written at every site; verbose, error-prone (102 refs). Migration artifact.
3. Fat `ControllerManagerContext` shared by all controllers embedding Client, Logger, creds, channels (pkg/context/controller_manager_context.go) - hidden coupling, hard to test in isolation; the `Logger` field coexists with `ctrl.LoggerFrom(ctx)`.
4. Global `sync.Mutex` held across network login in session cache (session.go:123-124); global package-level `sessionCache`; `session.Clear()` via defer in main.
5. Goroutine-per-task + unbuffered GenericEvent channel (util.go:263-335): leak on shutdown, lost on restart, no dedupe.
6. Cache-wait polling (5ms loop up to 5s) inside reconcile after patching to defend against stale cache (vspherevm_controller.go:~333): works but blocks worker; indicates non-idempotent external action being guarded by status written through a cached client.
7. No `TerminalError` for permanent failures; relies on error backoff forever; some "waiting for X" paths return nil and depend entirely on an event arriving (risk of stuck object if an event is dropped; SyncPeriod is the safety net).
8. Unchecked type assertions in predicate Funcs (vspherevm_controller.go:109-110) and unstructured-map assertions in webhook (vspherevm.go ~104-105). Untyped `predicate.Funcs` instead of `TypedFuncs[T]`.
9. Webhook immutability via delete-keys-from-unstructured-and-DeepEqual is clever but loses field-level error paths; the newer supervisor types use CEL which is better (XValidation).
10. `main.go` 845 lines with ~30 `os.Exit(1)` and mode detection by polling CRD presence at startup (30s) - controllers silently not started if CRD lags.
11. Log messages built with `fmt.Sprintf` inside `log.Info(...)` (e.g. `log.Info(fmt.Sprintf("Removing finalizer %s", ...))`, vspherevm_controller.go:421) instead of message + KV; inconsistent capitalization; contradicts structured-logging convention (the Capital/no-period rule is followed in most, not all).
12. Reconciler writes directly to cached `.Spec` in reconcile (e.g. `vmCtx.VSphereVM.Spec.BiosUUID = vm.BiosUUID`, :~498) and patches both spec and status in the same patch helper call - fine with patch helper but bundles spec+status writes (OpenShift/k8s API convention prefers separating).
13. Status contains operational/cache-ish fields (`taskRef`, `retryAfter`) with `ready *bool`; grandfathered exceptions to their own KAL rules.
14. Two ways to scope RBAC: markers in main.go for non-controller needs - OK, but markers for non-controller (CRD migrator) RBAC with giant `resourceNames=` line (main.go:271-273) are hard to maintain; they note in comments to keep in sync with crdMigratorConfig.
15. Public `webhooks/` alias package that only forwards to `internal/webhooks` - artifact of multi-module repo.
16. `os.Exit` before `defer session.Clear()`; deferred cleanup at end of `main` after `mgr.Start` returns - OK on clean shutdown, skipped on error exit.

## Reusable positives (for the skill)
- Per-controller concurrency flags with sensible big defaults + one global QPS/burst pair + `CacheSyncTimeout` bump for scale (main.go:142-169,233-242,613-618).
- `cache.Options.ByObject` + `Transform` + `DefaultTransform: TransformStripManagedFields()` + label selectors to cut memory; `client.Options.Cache.DisableFor` + explicit second cached client.
- Scheme built in one function, no global init.
- Typed generic webhook builder with `admission.Validator[T]`/`Defaulter[T]`, CEL XValidation for immutability.
