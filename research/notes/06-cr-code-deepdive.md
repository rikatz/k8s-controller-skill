## 1. PartialObjectMetadata / PartialObjectMetadataList

- Three independent informer maps per cache, one per representation: structured, unstructured, metadata. [V]
  ```go
  // cache/internal/informers.go:352-361
  case runtime.Unstructured:                 return ip.tracker.Unstructured
  case *metav1.PartialObjectMetadata, *metav1.PartialObjectMetadataList: return ip.tracker.Metadata
  default:                                   return ip.tracker.Structured
  ```
  Consequence: reading `*corev1.Secret` and `*metav1.PartialObjectMetadata{Secret}` creates TWO informers/two LIST+WATCH streams and two stores. builder `OnlyMetadata` + a typed `Get` anywhere = both caches (doc warning in builder/options.go:103-133). [V]
- Metadata informer uses `metadata.NewForConfigAndClient` (informers.go:483-495). `metadata.ConfigFor` forces `ContentType: application/vnd.kubernetes.protobuf` (cg-sibling `k8s.io/client-go@v0.37.0/metadata/metadata.go:64-73`). Structured informers use `apiutil.RESTClientForGVK`, which picks protobuf only for types in the client-go scheme (built-ins), JSON for CRDs (`client/apiutil/apimachinery.go:198-203`). [V] So for CRDs a metadata watch is cheaper on the wire AND in memory; for built-ins both are protobuf.
- Metadata list/watch fixes GVK onto every item/event (informers.go:507-510, 527; `newGVKFixupWatcher`) since the metadata client strips TypeMeta. [V]
- Requirement: the `PartialObjectMetadata` you pass to Get/List must have GVK set, else `GVKForObject` errors "unstructured object has no kind" (`client/apiutil/apimachinery.go:~120-130`, `isPartial` branch). For lists: `PartialObjectMetadataList` GVK Kind `FooList`; `objectTypeForListObject` chops "List" (cache/informer_cache.go:105-125). [V]
- Builder: `For/Owns/Watches(..., builder.OnlyMetadata)` and `WatchesMetadata` call `project()` which builds `PartialObjectMetadata` with the scheme GVK (builder/controller.go:290-305), then `source.TypedKind(mgr.GetCache(), projected, ...)` (controller.go:323,351,368). Handlers/predicates then receive `*metav1.PartialObjectMetadata` (so `EnqueueRequestForOwner` works: only needs ownerRefs; map funcs get metadata only). [V]
- What is lost: spec, status, data, everything except TypeMeta+ObjectMeta (name, ns, labels, annotations, ownerRefs, finalizers, deletionTimestamp, generation, RV, managedFields unless stripped). Writes: Create/Update on PartialObjectMetadata error; Patch uses the metadata client; DeleteAllOf has a metadata path (client/client.go:355-358,368-370,399-401,412-413). [V]
- Interaction with `cache.Options`:
  - `ByObject` keyed by GVK, NOT representation: `delegatingByGVKCache.cacheForObject` trims "List", `GVKForObject` => same GVK key for typed and metadata (cache/delegating_by_gvk_cache.go:110-125). So ByObject Namespaces/Label/Field/Transform/UnsafeDisableDeepCopy apply to BOTH the typed and metadata informers of that GVK. [V]
  - `Transform` (ByObject or Default) is installed on the metadata informer too (`SetTransform(ip.transform)`, informers.go:404): a transform asserting `*corev1.Pod` will see `*metav1.PartialObjectMetadata` objects there. Use `meta.Accessor`-style transforms (like `TransformStripManagedFields`, cache.go:414-423) or type-switch. [V]
  - Indexes: `IndexField(ctx, obj, ...)` attaches to the informer for obj's representation (informer_cache.go:203-209, GetInformer -> informersByType). An index registered with a typed obj is NOT visible to a `PartialObjectMetadataList` List with MatchingFields (different informer, no indexer => "Index with name field:x does not exist"). To index metadata, call `IndexField` with a `*PartialObjectMetadata{GVK}` and an extractor that takes `*PartialObjectMetadata`. [V by structure; error text from cg thread_safe_store ByIndex, not re-read -> [U] for exact text]
- `client.Options.Cache.DisableFor` is keyed by GVK only (client.go:297-319 `shouldBypassCache`: `c.uncachedGVKs[gvk]` before any representation check). => With `DisableFor: Secret`, a `Get(&PartialObjectMetadata{Secret})` via `mgr.GetClient()` goes LIVE to the API server (metadata client), not to the metadata cache. The 05-blog pattern "DisableFor + metadata-only watch" works for triggering (watch uses `mgr.GetCache()` directly) but metadata reads through the client are uncached. [V]
- Read-your-writes barriers are scoped by (gvk, representation) (client/consistency.go:~96-110). [V]

## 2. Indexers

- Per informer, i.e. per (cache, representation, GVK) and, with namespaced multi-namespace caches, per namespace cache. `multiNamespaceCache.IndexField` loops every namespace cache (multi_namespace_cache.go:210-226); cluster-scoped goes to `clusterCache`. `delegatingByGVKCache.IndexField` routes by GVK to the ByObject cache (delegating_by_gvk_cache.go:102-108). [V]
- Key format: index name `"field:" + field` (cache_reader.go:243-247). Values stored as `ns + "/" + val` AND `"__all_namespaces/" + val` for namespaced objects; cluster-scoped objects get only `"__all_namespaces/" + val`. [V]
  ```go
  // cache/informer_cache.go:226-241 (excerpt)
  vals[i] = internal.KeyToNamespacedKey(ns, rawVal)                  // "<ns>/<val>"
  if ns != "" { vals[i+len(rawVals)] = internal.KeyToNamespacedKey("", rawVal) } // "__all_namespaces/<val>"
  ```
  Cost: every indexed value is stored twice per namespaced object; index funcs run under the store write lock on every add/update/delete (cg thread_safe_store `updateSingleIndex`, calls indexFunc for old and new object). If your extractor panics or returns error CR wraps nothing: client-go `panic`s on index func error (cg thread_safe_store.go:185-196). CR's wrapper only errors if the object is not a `client.Object`. Keep extractors pure/cheap/nil-safe. [V]
- Query: `List(..., client.MatchingFields{"spec.nodeName": n}, client.InNamespace(ns))` -> `byIndexes(indexer, reqs, ns)` uses `KeyToNamespacedKey(listOpts.Namespace, value)`; empty ns => "__all_namespaces". (cache_reader.go:121-130, 187-230.) Cross-namespace index is automatic: omit `InNamespace`. [V]
- Requirements/limits: [V]
  - Selector must be exact-match equality (`RequiresExactMatch`), else `"non-exact field matches are not supported by the cache"` (cache_reader.go:121-125). `!=`, `in` unsupported.
  - Multiple fields in MatchingFields: first requirement uses ByIndex, the rest are filtered by re-running their index funcs => every field needs a registered index, else `"index with name ... does not exist"` (cache_reader.go:210-213; first one errors in client-go ByIndex).
  - `Get` never uses field index (GetByKey, cache_reader.go:62-65). MatchingLabels is a linear scan over the (ns-)list (cache_reader.go:130-166). Limit is honoured, `Continue` rejected (117).
  - Built-in field names like `metadata.name`/`spec.nodeName` get NO implicit index in the cache; you must register them.
  - Duplicate `IndexField` on same type+field name: client-go `addIndexers` returns `indexer conflict` (cg thread_safe_store.go:155-161). Register each (type, field) once. [V]
- When to register: `IndexField` calls `GetInformer(ctx,obj,BlockUntilSynced(false))` (informer_cache.go:204) so it no longer blocks (fixed v0.24 per notes). Informer's `AddIndexers` works before AND after start (existing items re-indexed under lock, cg thread_safe_store.go:502-518; refused only if informer `stopped`, cg shared_informer.go:959-967). Best practice: register in `SetupWithManager`/before `mgr.Start` so the first List never hits a missing index. [V]
- `RemoveInformer` drops the informer and its indexers (informers.go:338-350); a later Get/List lazily re-creates one WITHOUT your indexes and without event handlers (Kind sources are bound to the old informer). Re-register indexes if you ever call RemoveInformer. [V]
- `MultiNamespace`: `Get` on namespace not in the map and no `AllNamespaces` entry => `"unable to get: ... unknown namespace for the cache"`; cluster-scoped `Get` drops `opts` (multi_namespace_cache.go:236 passes no `opts...`, so per-call UnsafeDisableDeepCopy is ignored there). List across namespaces iterates a Go map => unordered. [V]

## 3. Memory reduction

All in `cache/cache.go` unless noted.
- Precedence (cache.go:520-559, `defaultConfig` 580-600): ByObject.Namespaces[ns] -> ByObject (type level) -> DefaultNamespaces[ns] -> Default*. Defaulting is per-field "if nil take from fallback"; there is NO chaining of Transform: a ByObject.Transform REPLACES DefaultTransform (587-589). If DefaultTransform strips managedFields and you add a ByObject.Transform, call the strip fn inside yours. [V]
- `ByObject.Namespaces` must be nil for cluster-scoped types (510-512 error). Nil map => inherits DefaultNamespaces; empty non-nil map => all namespaces (docs 217-219, code 514-518). [V]
- `AllNamespaces` ("") key in Namespaces adds `metadata.namespace!=x` field selectors for every other explicitly listed namespace (534-541, 602-613). [V]
- Selectors are applied server-side on both list and watch (`ip.selector.ApplyToList(&opts)` informers.go:382,389) => objects outside never enter memory and `Get` returns NotFound for them. Namespace restriction is a REST namespace path (informers.go:442-446, restrictNamespaceBySelector 614-628). [V]
- `TransformStripManagedFields` (414-423): `meta.Accessor`, nil-check, `SetManagedFields(nil)`; skip on non-meta objects. Typical saving: managedFields dominates small objects. Not applied to `DeletedFinalStateUnknown` (topic 8). Transform runs BEFORE any other actor, in-place mutation is safe (cg delta_fifo.go:165-168), runs on the FIFO insert path => must be fast and idempotent (cg delta_fifo.go:168-176). [V]
- `UnsafeDisableDeepCopy`/`DefaultUnsafeDisableDeepCopy`/per-call `client.UnsafeDisableDeepCopy` (client/options.go:548-568, 625-665): skips `DeepCopyObject` in `CacheReader.Get/List` (cache_reader.go:85-91, 167-175) AND skips resetting GVK on the result (101-103, 174). Risks: mutating the returned object corrupts the shared store and races with other readers/handlers; typed objects returned have EMPTY TypeMeta. Safe only for read-only use. [V]
- `ReaderFailOnMissingInformer` (informer_cache.go:173-178 -> informers.go:313-315): `Get/List` of a type with no informer returns `*ErrResourceNotCached` instead of silently creating a full informer (the classic "I accidentally cached all Secrets" bug). Note: with it on, you must have registered the informer (a controller For/Owns/Watches or `GetInformer`) before reading. [V]
- Pre-start `Get` side effect: `Informers.Get` creates the informer entry BEFORE checking `started`, then `informerCache.Get` returns `ErrCacheNotStarted` (informers.go:309-335 + informer_cache.go:71-78) => a pre-Start read still registers an informer. [V]
- `SyncPeriod` (cache.go:94-128, default 10h = line 45; `calculateResyncPeriod` jitter [0.9,1.1) informers.go:602-609) is applied as the informer's default resync, and every CR event handler inherits it (handlers added without own period, `source/internal/kind.go:112`). Resync = `SyncAll` -> `handler.OnUpdate(obj,obj)` for all store items (cg controller.go:~846-851, processDeltas SyncAll). Not API traffic. Also, a relist after watch drop produces Updates with unchanged RV which client-go treats as "sync" (cg shared_informer.go:1096-1105). [V]
- `DefaultEnableWatchBookmarks` default true (cache.go:465). `DefaultWatchErrorHandler` is set on every informer via `SetWatchErrorHandlerWithContext` (informers.go:396-401; cache.go:464). [V]
- `client.CacheOptions.Unstructured` default false => unstructured reads bypass the cache (client.go:314-317; cluster.go:204-208 default `Unstructured:false`). Setting true makes a THIRD informer family (unstructured) with full objects. `DisableFor` => no informer is created by reads (but any For/Owns/Watches still creates one). [V]
- Informer re-creation: `RemoveInformer` (see Section 2). There is no automatic re-creation on watch error; client-go reflector backs off and re-lists. [V]
- Multi-namespace caches multiply informers: one informer per type PER namespace (multi_namespace_cache.go:49-52, 101-108). With N namespaces and M types that is N*M watches; prefer one cluster-wide informer + label selector when N is large. [V]
- Per-informer overhead beyond objects: each registered handler gets its own buffered listener (client-go processorListener) - not measured. [U]

- WarningHandler: client defaults to `log.NewKubeAPIWarningLogger{Deduplicate:false}` when neither `WarningHandler` nor `WarningHandlerWithContext` is set (client.go:177-184); to silence set `config.WarningHandlerWithContext = rest.NoWarnings{}` (doc 123-127). - `client.Options` fields (client.go:45-82): `HTTPClient, Scheme, Mapper, Cache *CacheOptions, DryRun *bool, FieldOwner string, FieldValidation string, Log`. `wrapClient` wraps DryRun, then `WithFieldOwner`, then `WithFieldValidation` (153-165). - Update vs Patch vs Apply: Update = full-object PUT (serialises whole object; fails on conflict via RV; drops unknown fields of newer API versions - see MergeFromWithOptimisticLock doc patch.go:49-55). `MergeFrom(orig)` = client-side JSON marshal of orig and modified + `jsonpatch.CreateMergePatch` (patch.go:109-133): 2 marshals + diff CPU, small body; lists (finalizers, ownerRefs, conditions) are replaced wholesale (doc 156-163), and an empty diff still sends a `{}` PATCH (no short-circuit in `typedClient.Patch` [U - not re-read]). `StrategicMergeFrom` does not work on CRDs (patch.go doc ~177). `MergeFromWithOptimisticLock{}` puts resourceVersion into the patch => 409 on conflict, errors if RV empty (patch.go:92-103). [V]

A List of 10k Pods = 10k deep copies per call; mitigations: narrow with an index, use `PartialObjectMetadataList`, or `client.UnsafeDisableDeepCopy` for read-only. [V]
- `mgr.GetAPIReader()` is a plain `client.New` without Cache (cluster.go:221-227). [V]

### 7c Read-your-writes
- Field path: `ctrl.Options{Client: client.Options{Cache: &client.CacheOptions{EnableReadYourWritesConsistency: new(true)}}}` (client/client.go:97-115; manager->cluster default fills `Cache.Reader` if you provide a non-nil `Cache` struct, cluster.go:204-210). The v0.25.0 release-note shorthand `Client.EnableReadYourWritesConsistency` is NOT a field on `client.Options` (client.go:45-82). [V]
- Enabled only if the cache reader implements `cacheapi.Informers`, else `New` errors (client.go:267-270). Wraps the client in `consistentClient` (272-277). [V]
- Mechanics: reads wait until the informer for the (GVK, representation) has observed the highest RV written by this client for that key (Get) or GVK (List) and all pending deletes were observed (consistency.go:158-262; internal/consistencyhandler/consistencyhandler.go:169-258). Wait is bounded ONLY by the read's ctx - no internal timeout (`waitForRV` selects on ctx.Done only, 237-258), so pair with `ReconciliationTimeout`. [V]
- Caveats [V]: experimental; "does not work correctly when a resource has more than one Namespace configured" (client.go:111-112); per-call opt-out `client.DisableReadYourWritesConsistency` on reads and writes (options.go:203-246,338-341,420-423,554); RV is parsed as int64 (`observeResourceVersion` strconv.ParseInt, consistencyhandler.go:~260), relying on etcd-style numeric RVs (k8s says RVs are opaque -> [U] for non-etcd backends); a write whose object never reaches the cache (selector/namespace excluded, or a nil-returning Transform) cannot be "observed" by that informer's events -> reads of that GVK can wait until ctx timeout [U - inferred from handler design, not run]; metric `controller_runtime_client_consistency_wait_duration_seconds{operation,result}` (consistency.go:~48-58). Design PR #3473 merged AFTER the v0.25.2 tag (2026-10-05) so not in this tree.

## 8. (Extra) cache TransformFunc returning (nil, nil) to "drop" objects (kgame `TransformGatewayClass`)

Question: is `return nil, nil` a supported way to filter objects out of the cache? Answer: **NO. It is not supported, and in client-go 0.37 (what CR v0.25.2 uses, default feature gates) it can silently leave the informer with an EMPTY store, including the objects you wanted.** Use server-side label/field selectors (`ByObject.Label/Field`, `Namespaces`) instead.

Code path [V] (client-go v0.37.0, `tools/cache/`):
- CR installs the transform unchanged on the SharedIndexInformer (CR `cache/internal/informers.go:404`), the same func for structured, unstructured and metadata informers.
- `TransformFunc` doc: called for each object about to be stored, "MUST be idempotent if objects already present in the cache are passed to Replace()" (delta_fifo.go:160-176). Contract is "transform/normalize", nil is never mentioned.
- RealFIFO (the only FIFO, `InOrderInformers` GA locked, features/known_features.go:127-130; `newQueueFIFO` controller.go:1063-1096; AtomicFIFO default true, known_features.go:112-114):
  ```go
  // the_real_fifo.go:255-292 addToItems_locked
  _, err := f.keyOf(obj)                      // key computed from the ORIGINAL obj
  ...
  if f.transformer != nil { _, isTombstone := obj.(DeletedFinalStateUnknown)
      if !isTombstone && !skipTransform { obj, err = f.transformer(obj); if err != nil { return err } } }
  f.items = append(f.items, Delta{Type: deltaActionType, Object: obj})   // nil is queued as-is
  // the_real_fifo.go:296-310 addReplaceToItemsLocked: each list item -> transformer; nil kept inside ReplacedAllInfo.Objects
  ```
  No nil check anywhere. WatchList path also runs the transformer in the temporary store (`reflector.go:831-835,849`, `store.go:260-262,377-381` `cache.Add/Replace` store the nil value under the key computed pre-transform) and then `Replace` transforms AGAIN (so your transform runs twice per listed object on that path; kgame's `i.(*GatewayClass)` assertion on nil returns nil,nil again).
- Consumer side (`controller.go:823-890 processDeltas`; `processReplacedAllInfo` 972-1015; `the_real_fifo.go:636-660 reconcileReplacement`):
  - Replace/relist (initial LIST, WatchList, or relist after watch drop): `reconcileReplacement` calls `keyOf(obj)` on every item; for a nil it returns `KeyError` (`meta.Accessor(nil)` -> errNotObject, apimachinery meta.go:96-108) => the WHOLE `ReplacedAll` delta fails before `clientState.Replace` => no object of that list (including valid, non-nil ones) is stored and no OnAdd fires. The error is swallowed: `processLoop` ignores everything except `ErrFIFOClosed` (controller.go `processLoop`), and RealFIFO pop decrements `initialPopulationCount` in a defer even on error, so `HasSynced()` becomes TRUE with an empty store. [V by experiment]
  - Live Added/Updated with nil: `clientState.Get(nil)` errors -> goes to the `Add` branch -> `keyFunc(nil)` KeyError -> delta dropped (object never stored, no handler call). For an object that was stored and now flips to "not ours": the Update is dropped, the OLD object stays in the store forever (stale). Delete of a stored object whose transform returns nil: `clientState.Delete(nil)` fails -> stale entry remains. [V by experiment + code]
  - Batch path (`processDeltasInBatch` controller.go:892-967; `InOrderInformersBatchProcess` beta default true known_features.go:131) turns the nil into a Transaction whose key func fails (store.go:~365-390) -> `TransactionError`, only successful txns' callbacks run -> same effect: nil items silently skipped.
- No panic, no nil entry stored in the *indexer* in the live path; in the WatchList temporary store a nil VALUE is stored (store.go:260-262 + `cacheStorage.Add(key, obj)`), but it never reaches the main store.
- Experiment (`exp-nil-transform/main.go`; fake ListerWatcher with 2 ConfigMaps `ours`(label k=y) and `theirs`(k=n), transform returns nil,nil unless k=y; then live events: add theirs2, add ours2, modify ours->n, delete ours2). Outputs [V, run locally with client-go v0.37.0, `GOFLAGS=-mod=mod GOPROXY=off`]:

  | Config | After start | After live events |
  |---|---|---|
  | control: transform keeps all (`exp-ctl`) | synced=true, store=[ours theirs] | ok |
  | default feature gates (RealFIFO + AtomicFIFO + WatchList), list contains `theirs` | synced=true, **store = []** (even `ours` lost) | ours2 ADD handler fires but store stays [] |
  | `KUBE_FEATURE_AtomicFIFO=false` (+/- WatchList) | synced=true, store=[ours], ADD fires only for ours | `ours` stays in store after modify->not-ours (stale), delete of ours2 -> DEL ok |
  | `KUBE_FEATURE_WatchListClient=false` only | synced=true, store=[] | same as default |
  So behaviour depends on client-go feature gates (so it can change between client-go bumps) and is broken by default. [V]
- `DeletedFinalStateUnknown` and the transform: tombstones are explicitly NOT transformed (`isTombstone` skip, the_real_fifo.go:273-275; delta_fifo.go:499-505); the tombstone's `Obj` is the last queued/known object which was already transformed. `TransformStripManagedFields` is `meta.Accessor`-based and returns `(in, nil)` for non-meta input (cache.go:414-423), so tombstones/nil are harmless for it. Live `Deleted` events (real delete watch events) ARE transformed (RealFIFO `Delete` -> `addToItems_locked(Deleted,false,obj)`, the_real_fifo.go:~395-405), so a transform must return the object (not nil) for deletes too. [V]
- Supported filtering options [V]: (1) `ByObject{Label, Field}`/`DefaultLabelSelector`/`DefaultFieldSelector`/`Namespaces` = server-side selectors, objects never enter memory (informers.go:380-391). Field selectors only work for fields the API server supports for that resource (built-ins: a fixed few like `metadata.name`, `spec.nodeName` for pods; CRDs: only if the CRD declares `selectableFields`) - [U] not checked for GatewayClass `spec.controllerName`. (2) If you cannot select server-side: keep the object in the cache and filter in a predicate (`builder.WithPredicates`/`WithEventFilter`) and at the top of Reconcile; or use an informer-level `Transform` that returns the SAME object but shrinks it (e.g. drop `Spec`/`ManagedFields` for foreign objects) - still returns non-nil. (3) There is no CR API for client-side filtering at the store.
- Recommended fix for kgame-like code: replace `return nil, nil` with `return in, nil` (optionally after stripping bulky fields), and add a predicate comparing `Spec.ControllerName`.
